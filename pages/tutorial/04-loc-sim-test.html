3.1

学习目标

难度：进阶预计：4–5 小时前置：第 0–2 章

学完本章，你应该能：① 写出 RTK 相对单点定位提升精度的原理（差分消掉什么误差）；② 解释组合导航为什么必须“GNSS + IMU”互为补充；③ 用 ICP/NDT 的目标函数说明点云配准在干什么；④ 看懂 OpenDRIVE 车道元素的最小骨架；⑤ 把 SOTIF 的场景分区映射到测试策略。

3.2

定位问题的分层：三种信息来源

自动驾驶需要“车道级”定位：横向上要能分辨自己在哪条车道，误差通常要求分米级以内。定位是三类信息的融合：

🛰 全局观测

GNSS 给出绝对位置但有漂移、多径与遮挡；RTK 可到厘米级但依赖基站与开阔天空。

🌀 航位推算

IMU、轮速计短时高频且不受遮挡，但误差随时间积分发散（“越走越偏”）。

🗺 地图匹配与感知

激光/视觉与高精地图或道路特征匹配，得到相对车道的约束，误差有界但不一定处处可匹配。

三者单独都不可靠，组合才是答案：用 IMU 短时补 GNSS 的遮挡，用 GNSS/地图匹配校准 IMU 的漂移，这正是 3.5 的状态估计。

3.3

GNSS 与 RTK：伪距、载波与差分

单点定位：解伪距方程

接收机测量与卫星的距离（伪距），位置由至少 4 颗卫星联立解出（3 个坐标 + 1 个接收机钟差）：

ρᵢ = |r_satᵢ − r_rov| + c·dt + Iᵢ + Tᵢ + εᵢ

I 是电离层延迟、T 是对流层延迟、dt 是钟差。单点定位精度约米级，因为电离层延迟与钟差难以精确建模。

差分与 RTK：把共同误差“减掉”

RTK 的基本思想：基准站位置已知，它与流动站（车）在同一片天空下，两者的电离层/对流层/星历误差高度相关。把两站对同一卫星的观测相减，公共误差被消掉，只留几何差与模糊度：

单差：Δρ = ρ_rov − ρ_base ≈ Δr + c·Δdt
双差：对两颗卫星再做一次差，消掉接收机钟差
载波相位观测含整周模糊度 N：λ·φ = r + λ·N + …

载波相位精度远高于码相位（毫米级波长），但必须先估计整数模糊度 N：先求浮点解，再用 LAMBDA 等算法固定为整数（fixed），固定后可达 1–2 cm 精度。RTK 的弱点也清晰：离开基站覆盖、穿过城市峡谷时固定解丢失，会退化为分米~米级——所以要 IMU 在中间“撑着”。

3.4

IMU 与航位推算：高频但会漂

IMU 输出角速度（陀螺）与比力（加速度计），典型频率 100–1000 Hz。捷联惯导的思想是把这些增量连续积分出姿态、速度与位置：

姿态更新：q ← q ⊗ Δq(ω·Δt)
速度更新：v ← v + (R·a − g)·Δt
位置更新：p ← p + v·Δt

关键问题是零偏：静止时加速度计/陀螺仍有小偏置，积分一次变速度误差、两次变位置误差，并随时间增长；同时姿态误差会通过重力耦合到水平速度，形成“姿态漂 → 速度漂 → 位置漂”的恶性循环。

零偏模型

工程上把零偏建模为“随机游走”并放进状态向量估计：ḃ = 高斯白噪声。这正是组合导航里状态维数比“位置+速度+姿态”多 6 维（3 陀螺零偏 + 3 加速度计零偏）的原因。误差来源分清后，IMU 选型（零偏稳定性、噪声密度）与算法选型才能有的放矢。

3.5

组合导航：状态估计的经典应用

把 GNSS、IMU、轮速、地图匹配放进第 0 章的卡尔曼框架：

状态 x = [p, v, q(姿态), b_a, b_g]（15 维或更多）
预测：用 IMU 积分（高频率推进状态与协方差）
更新：GNSS 位置/速度、轮速、车道匹配等作为观测 z

“松组合”把 GNSS 解算好的位置/速度当观测；“紧组合”直接用原始伪距/载波观测做更新，遮挡时仍能利用未受污染的卫星，抗差能力更强。城市环境下“IMU + 轮速 + 车道匹配”可以撑住数秒到数十秒的 GNSS 盲区，这也是“隧道里也能开”的原因。

从滤波到因子图：SLAM/建图的视角

滤波只保留上一时刻估计（马尔可夫假设）；而建图时我们希望“全局一起调”，让所有历史位姿与观测互相修正。因子图把问题画成二分图：变量节点（每个时刻的位姿、地图点）+ 因子节点（相邻位姿间的里程计约束、与地图的观测约束、GNSS 先验）。目标是最小化所有因子残差的平方和：

min_X Σ_f ||r_f(X)||²_Σf

r_f 是某条约束的残差，Σf 是其协方差（权重）。求解用第 0 章的非线性最小二乘（高斯牛顿/LM）。这是理解激光 SLAM 后端（如 LIO-SAM、FAST-LIO 类系统）的一把钥匙：前端负责“匹配给了什么约束”，后端负责“把这些约束揉成一个一致地图”。

3.6

高精地图与点云/视觉匹配

点云配准：让两片点云对齐

定位到地图的本质是求一个位姿 T，使“当前帧点云”与“地图点云”最好地对齐。ICP 迭代最近点：每步把每个当前点关联到地图最近点，再求最优刚体变换：

min_{R,t} Σᵢ || R·pᵢ + t − q_j(i) ||²

q_j(i) 是 pᵢ 的最近邻。ICP 的缺点是依赖初始位姿与最近邻匹配质量。NDT（正态分布变换）把地图体素化成高斯分布，评分函数变成“当前点落在该分布上的概率密度之和”，对初值更鲁棒、工程上常用：

score(T) = Σᵢ exp( −½ (qᵢ − μ_j)ᵀ Σ_j⁻¹ (qᵢ − μ_j) )

视觉侧做类似的事：把“地图里的特征点/语义地标”重投影到图像，用重投影误差做位姿优化（见第 0 章 0.6）。激光测距稳但怕环境剧变与空旷路段，视觉/语义丰富但怕光照与视角变化——因此量产常做“激光几何 + 视觉语义”的互补匹配。

高精地图的数据结构：以 OpenDRIVE 为例

车道级高精地图至少分三层：导航层（道路连接关系，类似普通导航地图）、车道层（车道几何、宽度、与相邻车道的拓扑）、定位/属性层（交通标志、停止线、限速等）。OpenDRIVE 用 XML 描述这些元素，最小骨架大致是：

OpenDRIVE └─ road（一条路） ├─ planView：道路中心线的几何段（直线/螺旋/圆弧） ├─ elevationProfile / lateralProfile：高程与横坡 ├─ lanes：车道集合 │ ├─ laneSection │ └─ lane：含 id（左正右负）、宽度、类型（driving/curb…） ├─ link：道路之间的连接关系 └─ signals/objects：交通标志与路侧对象

地图必须与“在线感知”互为校验：地图说限速、感知说路障，冲突时按更保守者处理。众包更新与 OTA 是地图保鲜的工程主线——静止的地图是“昨天的世界”，而车端真正消费的是“本地化之后的车道拓扑”。

3.7

仿真与测试体系：验证金字塔

无人驾驶无法用“开到 10 亿公里再发布”来验证，必须把测试分层、让大部分验证发生在仿真里：

  1. 单元与模块测试

    感知单帧、跟踪单轨、单个规划函数的输入输出正确性（离线数据集上回归）。

  2. 场景仿真

    在可控场景里跑“整车闭环”：本车 + 交通参与者 + 传感器模型。分为真实数据回放、参数化场景（改变速度/距离/天气组合）与生成式场景。

  3. 封闭场地与实车路测

    仿真验证不了的传感器物理、执行器时延、人机交互，在试验场和限定 ODD 的真实道路收尾。

场景是测试的基本单位，至少包含五类元素：道路结构、静态物体、动态交通参与者、环境条件（光照/雨雾）、传感器与执行器状态。测试的价值来自覆盖度：不是“测了多少小时”，而是这些元素组合覆盖了多少比例的危险区间。

世界模型与生成式仿真

传统参数化场景靠工程师写模板，覆盖长尾效率低。生成式世界模型（见 AI 前沿专题）能从真实数据“改写”出罕见变体，用可控条件批量生成困难场景；其价值是扩大测试分布，但不能替代真实传感器物理回归。

3.8

SOTIF 与安全指标：把“没想到”也管起来

传统功能安全（ISO 26262）处理“系统坏了怎么办”：电子故障有概率模型可分析。但智驾更大的风险是“系统没坏、却遇到设计没想到的场景”——这就是预期功能安全 SOTIF（ISO 21448）的领域。

SOTIF 把运行场景按“是否已知 + 是否安全”分成四类：

已知未知
安全验证过、放行通过场景挖掘不断“未知 → 已知”
危险必须修复或限制 ODD核心风险：用功能不足分析 + 运行监控兜底

工程动作对应为：系统性识别“功能局限”（如传感器雨雾退化、规划对异形车误判）→ 设计运行监控与降级 → 用仿真/路测持续把未知危险场景转化为已知并回归。ISO 26262 的 ASIL 等级则按严重度 S、暴露率 E、可控性 C 组合划分 A–D，D 最高（如高速无冗余的转向控制）。两者叠加构成“功能失效 + 功能不足”的双重保障叙事。

📏 接管/干预率

MPI（两次人工接管间的行驶里程）是 L2/L3 时代最常用粗指标，但“接管原因”比次数更重要。

📉 影子模式指标

系统与人类驾驶员并行“想象驾驶”，统计两者决策分歧的严重度，用于挖长尾。

🔒 安全缓冲区指标

如与障碍最小间距、TTC（碰撞时间）、预测违反约束率——比“出没出事故”更早反映风险。

3.9

数据闭环：让系统越开越聪明

感知/规划的每个模型版本都依赖数据喂养。完整闭环是：

路采/影子模式触发采集 → 自动挖掘（按 TTC、接管、预测误差、模型低置信度等打分筛选） → 标注（3D 框、车道、占用、语义；人工 + 自动标注 + 交叉质检） → 清洗与均衡（按场景要素去重、补长尾） → 训练 / 仿真回归 / 安全关键场景回归 → 灰度 OTA → 回到采集

数据工程与算法同等重要，三个常被低估的细节：

  • 标注一致性：同一条车道线两个人标出两种结果，等于给模型喂噪声；需要标注规范与自动质检。
  • 分布审计：模型变好可能只是“训练分布越来越像旧测试集”，要用留出的分布外数据持续审计。
  • 回放 ≠ 闭环：回放旧数据只能回归旧决策；真正验证要能“把模型换进去重放、看它是否会撞”，即仿真闭环。
3.10

进阶：ESKF 与因子图优化

① 误差状态卡尔曼滤波（ESKF）

组合导航中状态含姿态（四元数），直接在流形上做 KF 会遇到归一化约束问题。ESKF 的做法是：名义状态用 IMU 积分传播，滤波器只估计误差状态 δx（姿态误差、速度误差、位置误差、零偏），再把修正量注入名义状态并重置。这样误差小、线性化准确，是工业组合导航的主流实现。

名义传播：x_nom ← f(x_nom, u)
误差传播：δx ← F·δx + w
观测更新：δx̂ = K·(z − h(x_nom))
注入并重置：x_nom ← x_nom ⊕ δx̂，δx ← 0

② 因子图与滑动窗口优化

把每一时刻的状态看作节点、每种观测（IMU 预积分、GNSS、视觉、激光）看作因子，整个定位问题就变成最大后验估计：

x̂ = argmin_x Σ_i || r_i(x) ||²_{Σ_i}

用高斯-牛顿或 Levenberg-Marquardt 迭代求解。为控制计算量，通常用滑动窗口只保留最近若干关键帧，并对旧状态做边缘化（marginalization）以保留其约束。这是 VINS-Mono、LIO-SAM 等系统的核心框架。

3.11

RTK/PPK 工作流与坐标系：从卫星信号到车体位置

3.3 节讲了 RTK 为什么能达到厘米级，这一节讲工程上怎么把它跑起来、以及“厘米级”是怎么被坐标系与工程细节吃掉的。

完整数据链路

卫星（多星座：GPS/BDS/GAL/GLO） │ 原始观测：伪距、载波相位、多普勒 ▼ 接收机（车端流动站） 差分改正数（RTCM 格式） │ ▲ │ NTRIP 客户端 ────────────────┘ 来自基准站 / CORS 网络（4G/5G 或电台） ▼ RTK 解算：双差 → 浮点解 → 模糊度固定（LAMBDA）→ 固定解/浮动解 ▼ 输出：WGS84 经纬高 + 速度 + 定位状态（固定解/浮动解/单点） ▼ 坐标转换：WGS84 → 局部坐标（UTM/高斯投影 或 ENU）→ 车体坐标 ▼ 与 IMU/轮速/点云匹配融合（3.5 节）

坐标系统一：最容易出错的一步

坐标系定义常见坑
WGS84 大地坐标经纬度 + 椭球高高精度定位输出的是椭球高，而地图/规划需要的是海拔或相对地面高度，两者差一个大地水准面差距（数米）
UTM / 高斯投影平面坐标把地球投影到平面（米制）投影带边界处变形大；跨带必须转换，否则位置差数十米
ENU 局部坐标以某原点（如起点或地图原点）建立东-北-天坐标系必须记录原点，否则日志回放会整体偏移
车体系x 前、y 左、z 上（ISO 8855）GNSS 天线不在车体原点，需要杆臂补偿（lever arm）
杆臂补偿：p_body = p_antenna − R_body·t_antenna_body
ENU 转换（局部切线近似）：东 = (λ − λ₀)·cosφ₀·(π/180)·R，北 = (φ − φ₀)·(π/180)·R，R ≈ 6371000 m

PPK：把“实时”换成“更稳”

PPK（后处理动态差分）用同一套载波相位观测，但把模糊度解算放到事后做，好处是可以用双向滤波、把整段数据一起解，固定率更高、无需实时链路。它常用于建图与真值生成：先采数据，回到办公室后处理出厘米级轨迹，作为评测其他定位算法的参考真值。

验收与失效

① 永远记录定位状态（固定/浮动/单点）与卫星数、PDOP、基线长度，只有固定解才能声称厘米级；② 城市峡谷、高架下、隧道进出口的固定解会丢失，定位系统必须由 IMU 与地图匹配接续，并把“降级区间”如实记录；③ 天线安装要远离干扰源（雷达、大功率线缆），否则多路径误差会让固定解忽隐忽现。

3.12

激光惯性里程计（LIO）：系统对比与实操

激光里程计提供“相对地图的厘米级局部定位”，是隧道、地下车库与城市峡谷中 GPS 失效时的主力。它要做三件事：点云配准（求帧间位姿）、IMU 预积分（提供高频与去畸变）、以及把两者放进滤波或因子图一起优化。

四个代表性系统

系统后端形式特点适合场景
LOAM / LeGO-LOAM扫描匹配 + 位姿图特征（边缘/平面）匹配的开创性工作；LeGO 做了地面分割，轻量学习原理、地面车辆
LIO-SAM因子图（GTSAM，含 IMU 预积分 + GPS 因子）结构清晰、易扩展（可加 GPS/回环），工程常用建图、组合定位
FAST-LIO / FAST-LIO2迭代 EKF（ikd-Tree 增量地图）直接法、无特征提取、速度很快，CPU 上可实时量产级实时定位
KISS-ICPICP + 极简管线代码极短、几乎无参数、鲁棒性好入门读源码、快速基线

环节关键参数经验取值与影响

去畸变每点时间戳 + IMU 插值不做去畸变在 10 m/s 下会带来分米级误差（见 1.11 节）
配准最大对应距离、迭代次数0.5–1 m / 5–10 次；过大易误匹配，过小会“配不动”
IMU 预积分噪声密度、零偏随机游走直接取自 IMU 数据手册，需用静止段验证
地图管理局部地图尺寸、关键帧间距局部地图 100–200 m；关键帧 1 m / 10° 量级
LIO 的四个失效场景

① 长直隧道或无特征走廊：几何约束退化，必须靠 IMU 与轮速维持，并监控协方差是否膨胀；② 大范围动态物体（车流密集）：动态点会污染配准，需要动态点剔除或鲁棒核；③ 时间同步不当：IMU 与激光时间戳偏差直接变成尺度与姿态误差；④ 外参错误：IMU 与激光之间的外参（旋转为主）错 1° 就会让转弯时位置误差累积。上线前务必用回环误差与已知控制点（如标定场）验证。

3.13

高精地图格式与生产：从采集到可用的地图

高精地图是定位与规划的“先验”：定位靠它找参照（车道匹配），规划靠它确定合法行驶空间（车道、路口、限速）。工程上关心两件事：地图格式表达力够不够、地图精度与新鲜度能不能维持。

三种主流格式

格式 / 体系数据模型优点缺点
ASAM OpenDRIVE道路几何（参考线、车道、连接关系、信号、物体）国际标准，仿真器（CARLA/SUMO）与工具链支持好偏几何描述，复杂语义（如复杂路口的通行规则）表达有限
Lanelet2车道段（lanelet）+ 规则（regulatory element）开源、规则可编程，与 Autoware/ROS 生态贴合非标准，跨厂商交换需转换
Apollo 地图（protobuf）车道、路口、停止线、信号灯、逻辑关系面向规划决策的语义完整与 Apollo 平台绑定，转换成本高
OpenDRIVE 最小骨架：road → 参考线（geometry：直线/螺旋线/圆弧/多项式）
　　　　　　　　　→ lanes（left/right，含 width、speed、lane type）
　　　　　　　　　→ junction（连接关系）与 signal / object

地图生产流水线

  1. 采集

    配备高精度组合导航（RTK/PPK + IMU）与激光/环视相机的采集车，按路线重复采集以提高一致性。轨迹精度直接决定地图精度上限。

  2. 建图与配准

    用 LIO/SLAM 建点云地图，再用 PPK 轨迹做全局约束（回环 + GNSS 因子），最后与已有地图做配准获得统一坐标。

  3. 要素提取

    车道线、路沿、停止线、斑马线、箭头：可自动提取（深度学习 + 几何拟合）再人工精修；信号灯位置需要多帧三角化并逐帧核对。

  4. 拓扑与规则

    把几何要素组织成车道连通关系、路口通行规则、限速与禁行信息——这一步决定规划是否“合法”，通常需要人工与规则引擎结合。

  5. 质检与发布

    质检指标包括几何精度（与实测轨迹偏差，目标 < 0.2–0.5 m）、要素召回率、拓扑连通性、坐标系一致性；发布采用版本号 + 差分包，配合 OTA 更新与灰度。

“轻地图”趋势

维护高精地图成本极高（道路每月都在变）。近年趋势是用感知 + 轻量语义地图（甚至只保留车道级拓扑与少量先验）降低维护成本，代价是定位与规划更依赖实时感知，对感知可靠性的要求随之上升。

3.14

仿真实操：CARLA / SUMO / OpenSCENARIO 怎么配合

3.7 节讲了验证金字塔，这一节给出“从零搭一套仿真回归”的具体做法。三个工具各司其职：CARLA 提供传感器级仿真与车辆动力学，SUMO 提供大规模交通流，OpenSCENARIO 描述你要考的场景。

分工与典型组合

工具角色输出常见组合
CARLA传感器级仿真（相机/激光/雷达真值、天气光照）图像/点云/真值框、碰撞与违规事件被测算法在环（SIL），配 ScenarioRunner 执行场景
SUMO微观交通流仿真（车流、信号配时）车辆轨迹与交通统计为 CARLA 提供背景车流；宏观策略验证
OpenSCENARIO / OpenDRIVE场景与地图描述（标准格式）可复用的场景文件（.xosc）与路网（.xodr）场景库 + 自动批跑 + 回归报告

搭一套场景回归的最小流程

1) 定义场景：路网（.xodr，可从 OpenDRIVE 编辑器或 CARLA 导出） 2) 写场景文件（.xosc 或 Python 版 ScenarioRunner 脚本）： 触发条件（Trigger）+ 参与者动作（Maneuver）+ 判定条件（Success/Failure 准则） 3) 批跑：为每个场景设置参数范围（速度、间距、天气、触发时刻），生成 N 个变体 4) 采集指标：路线完成率、碰撞（分类型：车/人/静态物）、违规 （闯红灯、压实线、超速）、舒适度（jerk、加速度极值）、接管次数 5) 回归比对：与上一版本逐场景对比，标出“新出现的失败场景” 6) 失败场景进入人工分析 → 修复 → 加入常驻回归集
# ScenarioRunner 执行示例（命令行） python scenario_runner.py --scenario my_cutin.xosc \ --repetitions 20 --output --outputDir results/ \ --timeout 60 # 各工具生态：CARLA 场景执行器 ScenarioRunner、Python 场景生成 scenariogeneration
仿真的三个陷阱

① 场景过拟合：只在少数“精调过”的场景里通过，必须做参数随机化与场景变体；② 传感器太理想：仿真里没有脏污、雨滴、镜头光晕与时间同步误差，需要主动注入噪声与延迟才接近真车；③ 只测通过率不测“为什么失败”：必须保留完整的传感器与决策日志，否则无法定位是感知、预测还是规划的问题。

3.15

安全合规与场景挖掘：把“没想到”变成可管理项

3.8 节介绍了 SOTIF 与安全指标的思路，这里补齐两个标准体系的分工，以及工程上如何持续挖掘危险场景。

三个标准各自管什么

标准管的对象核心动作典型产出
ISO 26262（功能安全）E/E 系统失效（硬件故障、软件 bug）危害分析与风险评估（HARA）、ASIL 等级、安全机制与冗余安全需求、安全目标、故障树/失效模式分析、冗余设计验证
ISO 21448（SOTIF，预期功能安全）功能本身不足与可预见的误用（传感器退化、算法局限）定义 ODD、识别功能局限、场景分区（已知/未知 × 安全/不安全）、运行监控与降级场景清单、触发条件分析、降级策略、验证与确认证据
UL 4600（自动驾驶安全论证）整体安全案例（含 AI 与运营）构建安全论证（safety case）：主张—证据—反证，覆盖开发过程与运营安全案例文档、独立评审、持续监控计划

一句话记忆：26262 管“坏掉”，21448 管“不会”，UL 4600 管“怎么证明”。三者叠加构成完整的安全论证叙事。

ASIL 等级怎么定

ASIL = f(S 严重度, E 暴露率, C 可控性)，取三者组合最高档
例：高速行驶中无冗余的转向失控 → S3（致命）+ E4（高暴露）+ C3（难以控制）→ ASIL D

场景挖掘：从路采数据里把危险场景“捞出来”

触发信号说明典型产出
接管与急刹司机接管、AEB 触发、jerk 超阈值高价值难例，优先回放复核
TTC / 最小间距越界碰撞时间低于阈值或与障碍间距过小危险交互场景（加塞、鬼探头）
模型不确定度检测置信度低、占用预测方差大、规划求解失败感知/规划的能力边界样本
与仿真预测不一致实车行为与仿真器预测的行为分布差异大仿真器保真度问题 + 新场景
法规/规则事件压实线、闯黄灯、超速边缘合规风险场景
闭环到回归

挖出来的场景要“结构化”（提取地图、参与者、初速度、触发时刻），转成 OpenSCENARIO/仿真场景，加入常驻回归集，并标注来源与发现日期。这样每一次路测都能沉淀为可重复执行的测试用例，而不是停留在“遇到过”的口头经验。

3.18

自测题

Q6：为什么 RTK 输出的“厘米级”经常在日志里对不上？

多半是坐标系没统一：接收机给的是 WGS84 大地坐标（经纬高 + 椭球高），而地图/规划用 UTM 或 ENU，且高度常需转换为海拔；再加上天线杆臂未补偿，几米的系统偏差很常见。

Q7：LIO 在长隧道里为什么会发散？

隧道断面一致，几何约束在纵向退化为欠约束，配准无法提供前进方向信息；此时只能靠 IMU 与轮速推算，协方差持续增大，长时间就会明显漂移。需要监控协方差并配合地图/绝对观测修正。

Q8：Lanelet2 与 OpenDRIVE 的关键差别是什么？

OpenDRIVE 偏几何描述（道路与车道几何、连接关系），是国际通用交换格式；Lanelet2 把“车道段 + 交通规则元素”作为一等公民，规则可编程，更适合直接驱动规划决策，但需要转换才能跨厂商交换。

Q9：ISO 26262 与 ISO 21448 的分工用一句话概括？

26262 管“系统坏了怎么办”（随机硬件失效与系统性失效，靠安全机制与冗余），21448 管“系统没坏但能力不足怎么办”（可预见的误用与性能局限，靠 ODD 定义、场景覆盖与运行降级）。

Q10：为什么仿真能过、实车仍会失败？

仿真里传感器过理想、参与者行为过于理性、缺少脏污/延迟/光照退化等真实扰动，且场景集常被“精调”过。要缩小差距必须注入噪声与延迟、做参数随机化，并把实车挖出的场景持续回灌。

Q1：为什么 RTK 需要基准站？

需要基准站提供同一天空下的参考观测，做差分才能消掉电离层、对流层与星历等共同误差；单机无法获得这份“参考”。

Q2：为什么 IMU 零偏必须在线估计而不能出厂标定后不管？

零偏随温度、老化、振动缓慢变化，且积分后会被放大成位置漂移；在线把它放进状态向量由观测持续修正，是最有效的补偿方式。

Q3：ICP 的目标函数优化的是什么？前提条件是什么？

优化刚体变换使点对距离平方和最小；前提是初始位姿足够近、最近邻关联大致正确，否则会落入局部最优。

Q4：为什么 SOTIF 说“多测几百万公里”不能单独证明安全？

安全风险集中在极罕见场景，均匀随机路测很难命中；需要“场景化 + 按危险组合定向生成 + 覆盖度分析”来系统逼近未知危险区。

Q5：回放测试能代替仿真闭环测试吗？

不能。回放只检验“旧决策是否仍然复现”，仿真闭环把新版本模型放回场景重跑，才能发现“因为模型变了而新产生的危险行为”。
